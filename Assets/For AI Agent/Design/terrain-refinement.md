## 当前问题与证据

当前场景为 `Assets/Scenes/Main Game Scene.unity`，实时绑定 `Assets/MapMagic Graph.asset`。检查时 MapMagic 未生成，Scene 为透视视图。

上一版 `Assets/_Recovery/CablewayRidge_20260919_183949/BuildRidge.cs.txt` 使用宽而对称的平滑山脊剖面，抬升越强的位置越接近平均脊高，原生成地形的沟壑因此减弱。新山形直接写入 Terrain，并未经过 Graph 中的 Erosion 节点。

同一脚本给塔架设置至少11米的圆形整平核心，过渡到48米半径。周围山坡高于塔基时，这个整平范围会在坡面上形成碗状凹地。

实时采样显示，`tajia03 (3)` 周围20米处八个方向均高于塔基附近地面，约高0.9至2.8米。西侧上坡方向40米处约高34米，东侧下坡方向50米处约低6米。需要重做顺坡过渡，单纯平滑圆坑边缘不足以解决形态问题。

Terrain Tools 5.3.2 已安装。当前主地形每块1000米，513高度采样点，水平采样间距约1.95米。本轮优先处理能改变远观轮廓的坡肩与沟谷，不以细碎岩面或悬挑岩壁为目标。

## 早期方案的技术方法

使用已有地形能力，不新增地形插件。先根据塔架位置定向修整高度图的大形与平台，再对局部坡面加入与坡向一致的侵蚀细节。首版样段曾复用 MapMagic 的局部侵蚀函数。第二步扩展试算触发原生函数崩溃后，改为在 Unity 外部用 NumPy 计算沟槽和有限步数的水与泥沙搬运，再逐块使用 TerrainData 写回。后续不再通过编辑器求值调用该原生侵蚀函数，也不触发整个 Graph 重新生成。Terrain Tools 的不规则印章仍可用于以后人工补形，本轮没有使用内置笔刷。

塔脚保护范围按实际基础轮廓确定，并在外部逐渐过渡。取消每座塔统一圆形压平的处理。塔基、厂区平台和样段外边界保持约束，避免侵蚀后用圆形整平重新制造凹坑。当前1.95米采样间距用于中等尺度沟壑，不在本轮整体提高地形分辨率。

# 厂区高度整理

2026 年 10 月 9 日，用户要求只改物体高度，不修改地形，并明确同意厂房按低处落地，高坡侧允许埋入。

共测量 819 个物体单元，调整 833 个 Transform，包含 26 栋厂房、门卫室、大门、工业设备、围栏与散落物。九台分散空调按各自所在建筑处理，包含两套料仓的共同分组按两套完整设备分别处理，没有修改层级。网格使用最高细节层进行检查，建筑占地按约一米间距采样，散落物按底部网格轮廓接触地面。

建筑与基础采用占地低处高度，固定附件跟随建筑。散落物优先保持堆叠支撑关系，地形高于原支撑面时随整组抬至地形。修正一组原先高于屋顶约 1.35 米的通风设备。宿舍交叠范围内的六段落地围栏按地面放置，不跟随楼内支撑面。

检查全部 21193 个 Transform，只有预定的 833 个局部 Y 值变化，水平坐标、旋转、缩放、父子关系和其余 Transform 保持不变。182 个地形相关文件 SHA256 一致，地形数据没有脏标记。原地形采样比较误差小于 0.0001 米，来自 JSON 浮点记录精度。

已检查厂区整体、屋顶附件、堆叠物、门卫室和料仓的 Scene View 画面。大坡差建筑高坡侧可能遮住门窗和通道，这属于用户确认的放置取舍。未进行 Play Mode 测试，最终画面和通行由用户确认。

`Before/Main Game Scene.unity` 为调整前场景备份。`survey.json`、`supports.json`、`attachments.json` 记录检查依据，`plan.json` 和 `relationships.json` 记录最终分组及高度差，`verification.json` 与 `terrain-verification.json` 记录校验结果，`Previews/` 保存编辑器截图。这里的 C# 和 Node 脚本仅用于本次编辑器操作，不会进入 Unity 运行时代码。
